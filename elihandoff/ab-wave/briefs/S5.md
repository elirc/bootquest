   Pass = weighted ≥ 0.80 AND no `[w3]` missed. Unweighted (legacy) sets: plain coverage ≥ 0.80, exactly as today.
   The 80% floor (`EB_MIN_COVERAGE` or equivalent) is unchanged.
2. One exported pass predicate (TS + an `EB_PASS_SQL` fragment) used by every place that decides an explain-back
   pass today: `evidence.ts:290-298` (promotion leg b), `ladder.ts:275`, `xp.ts:139`, `ladder-service.ts:270-274`,
   so promotion, XP and the leg display can never disagree with `passed`.
3. On self-score (`ladder-service.ts:476-530`) and practice-score (`:585-645`) write one `eb_score_detail` row per
   evidence row (plain, weighted, w3_missed, missed_ids = the kp ids marked missed). `evidence.score` = weighted
   coverage for weighted sets, plain otherwise. Old evidence (no detail row) keeps its meaning.
4. Client (LadderPanes `:600-700`): render the weight as a chip and the text without the prefix (`stripKpWeight`,
   display only); the live preview shows weighted coverage and "every w3 needed"; the result screen says which w3 was
   missed. Keys still appear only after the answer is stored.
