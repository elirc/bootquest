# S3 weak spots, due now, one-command launch (clone bq-qw-s3, branch ab-s3)

Goal: the learner can see what they keep getting wrong, what is due beyond flashcards, and can start the app with
one command.
Read: RULINGS R4 "A3"; `S\council\C1-learning.md`, `C2-architecture.md` (Q2 re-cut), `C5-skeptic.md` ("what the plan
misses": launcher); REVIEW §5 "A3"; R4-app.md §2 (L-items on weakness/interleaving), §3 Stats/Due-now findings.

## Own
`server/src/api/stats-service.ts`; new `server/src/api/due-service.ts` (+ route file, one registration line in
`app.ts`); `client/src/pages/Stats.tsx` + new components; `Dashboard.tsx` `DueNowPanel` (`:204-246`) and a teaser
mount (S4 owns the fetch and slate section; S1 a focus card); your section of `shared/src/api-ext.ts`; client api own

Do NOT edit `ladder-service.ts` (S5). If you need its alt-set gate (`ebSetGate`, `:310-323`) and it is not
exported, you may add the word `export` to it and nothing else; say so in your report.

## Build
1. `GET /stats/weak`: per repo (and per module for drill banks), with counts and the newest example ids:
   quiz-miss review cards whose key the learner has seen (reuse the existing explanation-release rule), review lapses
   and Again grades, drill submissions that failed with no later pass, and missed explain-back key points from
   `eb_score_detail.missed_ids` (migration 018; S5 writes these rows: in your tests insert rows directly). Only show
   items whose key is already released. Sort by recency-weighted count; cap the list.
2. Stats page "Weak spots" panel with links to the units; dashboard teaser (top 3) rendered only when there is data.
3. `GET /due`: open retests (what Due now shows today) plus alternate explain-back sets whose rotation gate has opened
   (the 2-day gap stays as is; scaling it by score is deferred). `DueNowPanel` uses it and drops the "alt sets are not
   listed here" note (`Dashboard.tsx:224`).
4. Launcher: `npm run app` starts the API server and the UI from ONE terminal (either the server serves the built
   client, or one script runs both and stops both on Ctrl+C), refuses with a clear message when `BOOTQUEST_DB` is unset,
   prints the URL. Windows + Git Bash + cmd must all work. Keep the vite `fs.deny` protections: built client assets
   only, never `content/packs`. Update the README "Run it" section.

  (an alt set appears exactly when its gate opens). Client tests for the panel, the hidden-when-empty teaser and Due now.
- Launcher verified by actually starting it against a temp DB copy on another port (`BOOTQUEST_PORT`), never :4178.
