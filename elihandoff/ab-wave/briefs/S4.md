# S4 find things: search, dashboard targets, mixed drills (clone bq-qw-s4, branch ab-s4)

Goal: the learner can find any unit fast, the dashboard links straight to the next drill without an 11-request
fan-out, and drills can be practised interleaved across tracks.
Read: RULINGS R4 "A4"; `S\council\C2-architecture.md` (A4: measured index size, campaign-unit gap, targetUnitId),
`C5-skeptic.md` (cuts); REVIEW §5 "A4"; R4-app.md §3 scale/UX findings (`Dashboard.tsx:265-305`, `TrackUnits.tsx`).

## Own
`server/src/api/service.ts` `getDashboard` (`:764-806`) and new functions you add; new appended functions in
`store/queries.ts`; new route file(s) (one registration line in `app.ts`); `Dashboard.tsx` fetch (`:26-30`) and slate
section (`:265-393`); `TrackUnits.tsx`; new `CommandPalette` component (mount in `AppShell.tsx`); your section of
`shared/src/api-ext.ts`; client api own block; `client/src/api` dashboard fixture.

## Build
1. Dashboard `targetUnitId` per slate item, computed in the `getDashboard` response mapping (drill set → first
   passable, unrevealed drill of that track; campaign step → its unit). Add it to an extended DTO in api-ext. **Never
   add it to the stored `SlateItem`** (`daily_slate.items` JSON, frozen in closed days). Remove the
   `useSlateTargets` fan-out (`Dashboard.tsx:265-305`).
2. `GET /units/search?q=&limit=30`: server-side over unit key + title only (never prompts, key points or notes),
   includes the campaign study quests that `unitsForTrack` omits (`queries.ts:96-101`) with their act lock from
   `campaignState`; a locked unit shows title + `locked`, and opening it still hits the existing act gate.
3. `Ctrl+K` command palette (keyboard-first, accessible: role=dialog, focus trap, Esc, arrow keys, Enter opens) over
   that endpoint; add it to the shortcut help overlay.
4. Mixed drill mode: `GET /drills/next?tracks=js,java,sysdesign&mode=mixed` returns the next unpassed drill rotating
   deterministically across the given tracks (day + pass count; no Math.random); a "Mixed drills" entry on the
   dashboard. Stays in service/client code (no grader files).
5. Unit browser: groups collapsed by default on every track (render rows only for expanded groups), filter still
   works across everything.
6. Only if budget remains: `GET /repos/:name` + `/repo/:name` dossier page (units on a repo grouped by kind).

## Acceptance

- Search tests: campaign units included, locked act stays locked, no seed-item text searched or returned.
- Mixed-mode determinism test; palette keyboard tests; TrackUnits render-count test with a 4,000-row fixture.
