## Build
1. `enqueue` (`study-quest.ts:66`) stores `competency_id` from the unit's competencies (`unitCompetencies(unitId)[0]`,
   `queries.ts:47-55`) for quiz-miss and flashcard cards. Units with none stay NULL (no demotion, as today).
2. Demotion in `fsrs.ts` `review()` (`:180-189`): a lapse on a competency-linked card in Review state demotes at most
   once per competency per local day (check `evidence kind='demotion'` for that competency in today's bounds) and
   never writes a demotion row when the rating is already at the floor (1). A capped/floored lapse still logs the
   review normally. No `lapseWouldDemote` field, no confirm dialog on Again (RULINGS R3.2).
3. Repeat quiz miss (R4 L3, `study-quest.ts:70-76`): a miss on a quiz that already has a card re-grades that card as
   `again` (schedule shortens, lapse counted) instead of leaving it untouched. No XP change; idempotent per attempt.
4. Review paging (BUG-2), client-only: when the queue response says `count > items.length`, Review.tsx refetches the
   queue after the page is graded and continues; "Queue cleared" only when the server says 0 due. No offset param.
5. Copy: the Review page's demotion text and the README sentence state the real rule (once per competency per day,
   never below 1). Put the README change in your branch (README.md is not fingerprinted).
